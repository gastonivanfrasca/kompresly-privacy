2. Información que trata la Aplicación

Imágenes y datos asociados

Cuando el usuario selecciona imágenes, Kompresly utiliza el selector de fotos del sistema Android y recibe las referencias locales necesarias para trabajar con esas imágenes. La compresión se realiza en el dispositivo. En la compilación actual, el contenido de las imágenes, los nombres de archivo, las rutas o URI locales, los datos EXIF y los datos GPS no se envían a un servidor de Kompresly ni a un proveedor de analytics, crash reporting o publicidad.

La Aplicación puede leer los datos necesarios para decodificar y comprimir una imagen. Si el usuario activa Keep photo metadata, la compilación Android puede conservar metadatos JPEG compatibles, incluida información que podría revelar ubicación u otros datos sensibles. Si se desactiva esa opción, Kompresly no intenta conservar esos metadatos en el resultado. El usuario debe revisar los metadatos antes de compartir una imagen.

Preferencias y datos locales de la Aplicación

Kompresly guarda localmente las preferencias necesarias para recordar:

  • tamaño objetivo y unidad (KB o MB);
  • preferencia predeterminada de conservación de metadatos; y
  • el contador local de lotes completados utilizado por la lógica opcional de frecuencia de anuncios.

Estos valores se guardan en el almacenamiento local de la Aplicación. No requieren una cuenta y no se sincronizan con Kompresly.

Datos técnicos y eventos opcionales

La compilación actual mantiene Analytics y Crashlytics desactivados por defecto. El usuario puede otorgar o retirar por separado el consentimiento opcional desde Settings; sin ese consentimiento no se envían eventos de uso ni informes de errores a Firebase. Remote Config y Ads no están conectados en la compilación actual.

El código contiene límites para futuras integraciones. Si se activa un proveedor en una versión publicada, esta política y la ficha de seguridad de datos de Google Play deben actualizarse antes de distribuir esa versión.

3. Qué ocurre con las imágenes y los resultados

  • Los candidatos de compresión y los resultados de una sesión pueden existir temporalmente en el almacenamiento privado de la Aplicación.
  • La Aplicación elimina los archivos temporales que posee al cancelar, terminar una sesión y al iniciar una nueva ejecución cuando corresponde. La limpieza no elimina las imágenes originales del usuario.
  • Los originales no se sobrescriben.
  • Al pulsar Save o Save All, el usuario solicita que Android guarde una copia comprimida en la galería/MediaStore, en el álbum local de Kompresly cuando el sistema lo permite. Esa copia queda bajo el control del usuario y debe eliminarse desde la galería o el sistema operativo.
  • Al pulsar Share o Share All, Android abre el selector de compartir. La Aplicación entrega el resultado seleccionado a la aplicación o servicio que el usuario elija. El receptor puede tratar, almacenar o compartir la imagen conforme a su propia política de privacidad; Kompresly no controla esas prácticas.

La Aplicación no conserva una copia en la nube. El tiempo de permanencia de las copias guardadas en la galería o entregadas a otra aplicación depende del usuario, del sistema Android y del servicio receptor.

4. Permisos y servicios del sistema

La selección de imágenes utiliza el selector visual del sistema Android para que el usuario elija qué fotos compartir con la Aplicación. La Aplicación no necesita una cuenta ni está diseñada para solicitar acceso a cámara, micrófono, contactos, ubicación o audio.

En la compilación Android actual, el guardado utiliza el servicio MediaStore del sistema y no solicita permisos amplios de lectura de toda la galería. Dependiendo de la versión de Android y de la ruta de compatibilidad disponible en el dispositivo, Android puede mostrar un selector, confirmación o solicitud de permiso del sistema para seleccionar o guardar fotos. El usuario puede rechazarlo; en ese caso, la función afectada no estará disponible.

El sistema Android y las aplicaciones que el usuario elija para seleccionar, guardar o compartir pueden procesar información conforme a sus propias políticas. Esta política describe el tratamiento de Kompresly, no el de esos terceros.

5. Proveedores opcionales

Las siguientes integraciones son opcionales y están desactivadas por defecto. Si el usuario las activa desde Settings, puede retirarlas desde el mismo lugar.

Analytics

Si se activa analytics, el transporte permitido está limitado a eventos anónimos y a parámetros de producto como cantidad de fotos, tamaño objetivo, modo de compresión, preferencia de metadatos, duración, totales de tamaño y categorías cerradas de éxito o error. La implementación actual no permite enviar contenido de imagen, nombres de archivo, rutas, URI, EXIF, GPS ni identificadores de usuario.

Estado de Analytics: desactivado por defecto. Si el usuario lo habilita, la aplicación utiliza Firebase Analytics mediante @react-native-firebase/analytics para medir el uso agregado del producto y envía sólo los eventos y parámetros allow-listed descritos arriba. No se envían imágenes, nombres de archivo, rutas, URI, EXIF, GPS, identificadores de usuario ni datos de contacto. El consentimiento se guarda localmente y puede retirarse desde Settings; al retirarlo, la aplicación desactiva la recopilación.

La retención, los subencargados y las regiones de procesamiento de Firebase deben confirmarse en la consola y en la ficha Data safety antes de distribuir una versión que use esta opción. No se configuran identificadores de usuario ni propiedades de usuario en Kompresly.

Crash reporting

Si se activa crash reporting, la frontera actual sólo permite una clasificación del error: límite de captura, tipo de error y, cuando corresponde, un código cerrado de servicio. No se entrega el objeto de error, mensaje, stack trace, URI, nombre de archivo, EXIF, GPS, contenido de imagen ni identificador de usuario al adaptador previsto.

Estado de Crashlytics: desactivado por defecto. Si el usuario lo habilita, la aplicación utiliza Firebase Crashlytics mediante @react-native-firebase/crashlytics para recibir la clasificación allow-listed de errores descrita arriba. No se entrega el objeto Error, mensaje, stack trace, URI, nombre de archivo, EXIF, GPS, contenido de imagen ni identificador de usuario al adaptador de Kompresly. El consentimiento puede retirarse desde Settings.

La retención, los subencargados, las transferencias internacionales y los mecanismos de derechos de Firebase deben confirmarse en la consola y en la ficha Data safety antes de distribuir una versión que use esta opción.

Remote config

La configuración remota no está conectada a una red en la compilación actual; utiliza valores locales deterministas. Si se conecta un proveedor, debe documentarse qué datos técnicos recibe, para qué finalidad, durante cuánto tiempo, en qué países y cómo puede el usuario oponerse.

Estado de Remote Config: inactivo/no corresponde en la compilación actual.

No corresponde en la compilación actual: proveedor, SDK, datos, finalidad, retención, regiones y subencargados.

Publicidad

No se muestran anuncios en la compilación actual. Estado de Ads: inactivo/no corresponde en la compilación actual. No se informan proveedor, SDK, identificadores, categorías de datos, finalidad, personalización, consentimiento, retención, países, subencargados ni opciones de oposición porque la función no está activa.

No corresponde en la compilación actual: proveedor publicitario, SDK, identificadores y categorías de datos, finalidad, personalización y consentimiento, retención, países y subencargados, y opciones de oposición o eliminación de anuncios.

6. Base jurídica y elecciones del usuario

Cuando la legislación aplicable lo requiera, el tratamiento local necesario para prestar la función solicitada se basa en la ejecución del servicio pedido por el usuario. Cualquier analytics, publicidad o integración adicional que requiera consentimiento sólo debe activarse después de obtener el consentimiento válido y ofrecer una forma equivalente de retirarlo.

En el estado actual, el usuario puede:

  • seleccionar sólo las fotos que desea procesar;
  • cancelar el flujo de compresión;
  • desactivar la conservación predeterminada de metadatos en Settings;
  • no guardar ni compartir un resultado;
  • borrar las preferencias y datos locales desde los controles del sistema Android, borrar la Aplicación o desinstalarla; y
  • borrar desde la galería las copias que haya guardado.

Como no hay un proveedor de analytics, publicidad o crash reporting activo, actualmente no es necesario gestionar una baja de esos servicios dentro de Kompresly. Si se activa uno, se añadirán los controles y disclosures correspondientes antes de la publicación.

7. Derechos de privacidad

Según el país y la ley aplicable, el usuario puede tener derecho a solicitar acceso, corrección, eliminación, limitación u oposición al tratamiento, portabilidad, retiro del consentimiento y a presentar una reclamación ante la autoridad de protección de datos competente. Las solicitudes deben enviarse a gastonfrascadeveloper@gmail.com e incluir información suficiente para responder sin pedir datos innecesarios.

La mayor parte de la información de la compilación actual permanece en el dispositivo y puede gestionarse mediante Android, la galería o los controles de la Aplicación. Si en el futuro se activa un proveedor externo, el responsable coordinará las solicitudes aplicables con ese proveedor y describirá aquí el procedimiento actualizado.

Kompresly no crea cuentas ni perfiles de usuario en la compilación actual; por lo tanto, no existe una cuenta de Kompresly que el usuario deba solicitar eliminar. Si una versión futura incorpora cuentas, esta política deberá incluir un mecanismo claro para solicitar la eliminación de la cuenta y de los datos asociados antes de publicarse.

8. Seguridad

Kompresly aplica procesamiento local y limita los datos que sus adaptadores opcionales pueden recibir. Ningún método de almacenamiento o transmisión es completamente seguro; el usuario debe mantener actualizado Android, proteger el acceso al dispositivo y revisar los destinatarios antes de compartir imágenes.

9. Menores de edad

Kompresly no está dirigida específicamente a menores y no recopilamos deliberadamente información personal de menores. Si un padre, madre o tutor cree que un menor proporcionó información personal, puede contactar al responsable en gastonfrascadeveloper@gmail.com para solicitar su revisión y eliminación cuando corresponda.

10. Transferencias internacionales

La compilación actual no envía imágenes ni datos de uso a servidores de Kompresly o de proveedores externos. Si se activa un proveedor con procesamiento fuera del país del usuario, esta sección se actualizará con los países, mecanismos legales de transferencia, subencargados y salvaguardas aplicables antes de distribuir la versión correspondiente.

11. Cambios a esta política

Podemos actualizar esta política para reflejar cambios en la Aplicación, proveedores, leyes o prácticas de privacidad. La URL HTTPS pública de esta política está pendiente de despliegue; cuando se publique, actualizaremos esta referencia y la fecha de entrada en vigor y, cuando sea necesario, solicitaremos el consentimiento del usuario antes de activar un nuevo tratamiento.

12. Información pendiente para una publicación real

Antes de usar esta política como URL de la ficha de Google Play, queda pendiente desplegar una URL HTTPS pública, estable, no geobloqueada, accesible sin iniciar sesión, servida como una página no editable y no como PDF. Analytics y Crashlytics permanecen desactivados por defecto; Remote Config y Ads permanecen inactivos. La sección Data safety de Google Play deberá revisarse para que corresponda con la versión exacta que se publique y con el consentimiento opcional ofrecido.

Esta política describe el comportamiento actual del repositorio y no constituye asesoramiento legal.
